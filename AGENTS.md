# Base44 Dev Environment

## Stack
- Vite + React + TypeScript + Tailwind (shadcn/ui) frontend, generated by Lovable.
- Backend is a **hosted Supabase** project (`mgezyfbavbrwpghsgbnw.supabase.co`); no local DB or backend service runs in compose.
- Edge functions live under `supabase/functions/` and are deployed to Supabase (not run locally).
- `main` also carries `drizzle/` + `drizzle.config.ts` for its own DB migrations; they are **not** used by the frontend dev server (no `src/` file imports drizzle).

## Running
- `docker compose -f docker-compose.base44.yml up -d` — starts the Vite dev server on host port 3000 (container port 8080).
- Startup runs `npm install --no-package-lock` inside the container; `node_modules` is a named volume so reinstalls are skipped afterward.
  - `--no-package-lock` is deliberate: the committed `package-lock.json` predates the devDependencies `main` added, and a plain `npm install` rewrites it (npm 10 also prunes other platforms' optional deps) on every start, dirtying the working tree. `bun.lock` is the repo's canonical lockfile.
- Source is bind-mounted, so edits hot-reload via Vite HMR (polling enabled via `CHOKIDAR_USEPOLLING=true` for bind-mount reliability).
- `web` has a healthcheck that fetches `/` on 8080 (`start_period` 120s to cover the first install).

## Environment
- All required env vars (`VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_SUPABASE_PROJECT_ID`) are committed in the repo-root `.env`, which Vite auto-loads. These are public anon/publishable keys — **no user-supplied secrets are required**.
- No `BASE44_PREVIEW_MODE` behavior is needed here: the preview works through `server.allowedHosts`.

## Why the preview failed to start on `main` (commit 0968c0f)
- `main`'s `vite.config.ts` is unchanged from Lovable's original: `host: "::"` and **no `server.allowedHosts`**. Vite >= 5.4.12 rejects requests whose `Host` header is not allow-listed, so every preview request (the proxy sends `Host: 3000-<sandbox-id>.<domain>`) got `403 Blocked request. This host ("…") is not allowed.` — the page never went live.
- This branch's `vite.config.ts` keeps `server.allowedHosts: true` and `host: true`, which is what makes the preview serveable. **Do not re-apply main's version of this file** when merging.
- Everything else in `main` builds cleanly (`vite build` succeeds on `origin/main` in isolation, ~2670 modules).

## Verification
- `curl -sf -H "Host: external-preview.example.com" http://localhost:3000/` must return the app HTML (Vite dev, not a prebuilt bundle).
- `docker compose -f docker-compose.base44.yml exec -T web npm run build` is the fastest full-app check (catches import/type errors the dev server only hits per-module).
- `docker compose -f docker-compose.base44.yml exec -T web npx vitest run` runs the unit tests (`src/test/`).
- Routes: `/` (main app), `/reset-password`, `*` → NotFound.

## Design notes
- The all-competitions match query loads only a recent window, in parallel pages; per-competition queries keep full history. Why: the full table made the first screen take minutes on a small backend.
- Prediction views share a market catalog with Edge and derive goal probabilities from the existing Dixon-Coles matrix; unsupported markets stay unavailable. Why: avoid contradictory numbers, fabricated odds, and slow text-generation calls.
- Team selectors share the Fotmob roster union and explicit alias identities; fixtures share UTC-date/team deduplication before local-time rendering. Why: keep missing-table clubs selectable without merging distinct clubs or repeating games.

# Base44 Dev Environment

## Stack
- Vite + React + TypeScript + Tailwind (shadcn/ui) frontend, generated by Lovable.
- Backend is a **local Fotmob-backed API** (`server/`, Node, no deps) that replaces the
  original paused Lovable Supabase project. It fetches Fotmob's public API
  (`www.fotmob.com/api/data`) into memory and speaks the PostgREST + edge-function
  protocol the `supabase-js` client already uses, so the frontend is unchanged.
- The original Supabase edge functions live under `supabase/functions/` for reference;
  the Fotmob-fetching logic was ported into `server/fotmob.mjs`.
- Auth/realtime are stubbed (the main views aren't auth-gated); features that need a
  real user session (votes, profile, bet persistence) degrade gracefully.

## Running
- `docker compose -f docker-compose.base44.yml up -d` — starts two services:
  - `web` — Vite dev server on host port 3000 (container port 8080).
  - `api` — local Fotmob API (Node, `server/index.mjs`) on container port 8080.
- First boot runs `npm install` inside `web`; `node_modules` is a named volume so reinstalls are skipped afterward.
- Source is bind-mounted, so edits hot-reload via Vite HMR (polling enabled via `CHOKIDAR_USEPOLLING=true`).
- **Single-origin wiring:** `vite.config.ts` proxies `/rest`, `/functions`, `/auth`, `/realtime`
  from the page origin (port 3000) to `http://api:8080`. The `supabase-js` client is
  pointed at the page's own origin, so the browser makes same-origin calls only.
- The api fetches all leagues from Fotmob on startup (parallel, ~15s) and refreshes
  fixtures/results every 15 min, live matches every 30 s, standings every 6 h.

## Environment
- `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_SUPABASE_PROJECT_ID` are
  injected via the `web` service `environment:` (page origin + a dummy key) — not real
  secrets. `.env` is intentionally empty; the platform secret store is unused here.
- `vite.config.ts` sets `server.allowedHosts: true` and `host: true` so the preview's external hostname is accepted.

## Verification
- `curl -sf -H "Host: external-preview.example.com" http://localhost:3000/` must return the app HTML (Vite dev, not a prebuilt bundle).
- Routes: `/` (main app), `/reset-password`, `*` → NotFound.

## App notes
- The all-competitions match query loads only a recent window, in parallel pages; per-competition queries keep full history. Why: the full table made the first screen take minutes on a small backend.
- Prediction views share a market catalog with Edge and derive goal probabilities from the existing Dixon-Coles matrix; unsupported markets stay unavailable. Why: avoid contradictory numbers, fabricated odds, and slow text-generation calls.
- Team selectors share the Fotmob roster union and explicit alias identities; fixtures share UTC-date/team deduplication before local-time rendering. Why: keep missing-table clubs selectable without merging distinct clubs or repeating games.
